# パイロット報告: Lantern Guild Season

- 入力: `examples/lantern_guild_season/`（3パーティー、5地域、シード 20261001）
- 範囲: シーズン開始ドラフト → 行動ターン1〜4 → 中盤ドラフト（ターン5）→ 行動ターン5〜6 → ターン7のアップキープ確認後に終了
- 実施方法: 1つのAIエージェントがGMと全パーティーを順に担当し、エンジンの5ツールで処理した
- 記録: `playlog.jsonl`（8エントリ）、`world_final.json`

## 数値

| 指標 | パイロット | 既存リプレイ3本 |
|---|---|---|
| プレイログに残る行動者 | GM＋3パーティー（全行動） | GMのみ |
| 行動種別のエントロピー | 2.81 bit（10種） | 1.40〜1.60 bit（4種） |
| 1エントリあたりの効果＋判定数（行動ターン） | 6〜13（減衰なし） | 2本で終盤1まで減衰 |
| 判定 | 21回（成功10・部分成功5・失敗6） | なし |
| パーティー対パーティーの対抗判定 | 5回 | なし |
| 拒否された応答 | 1件／約33件（GMのスキーマ不整合） | 該当なし |

依頼の決着: 達成2（cove_map: 銀羽根団、ledger_to_ora: 灰灯団）、衝突による失敗1、期限切れ2。クロックは2つとも満了した（密輸団の港支配、旧市街の隔離）。暫定順位: 銀羽根団2、灰灯団1、鉄狼団0。

ターン数が短いため、終盤に効果数が落ちないかは確認できていない。

## 狙いどおりに機能した点

- **衝突の構図はドラフトで決まった**: 2回のドラフトとも、両立しない依頼の組を別々のパーティーが取った。以後の5回の対抗判定はすべて、その組の当事者の間で起きた。GMが対立を仕込む必要はなかった。
- **指名が互いへの反応になった**:
  - 鉄狼団は、銀羽根団が欲しがる治療師を押さえた。
  - 銀羽根団は、オラに雇われるはずだった荒くれを先に雇った（妨害目的の指名）。
  - 銀羽根団の誘いを、鉄狼団が「誇り」の欠点に従って公開の場で断った。
- **失敗が展開を作った**:
  - 鉄狼団の護衛は、妨害を受けて期限切れになった。
  - 灰灯団の台帳の達成により、鉄狼団の判事の依頼は自動で失敗した。
  - 依頼主の感情（-1）と2つのクロックの満了が、後の状況として残った。
- **情報の差が判断に効いた**: 銀羽根団は判定でヴェルの秘密を暴き、買った情報からオラの買い手の居場所を知った。他のパーティーはどちらも知らない。

## 発見した不具合（すべて修正済み）

1. GMがパーティーに課した判定と、そのパーティー自身の判定が、同じダイスになっていた。
2. 応答の処理順で結果が変わっていた。妨害と進捗が同じターンに重なると、先に0で丸められていた。
3. `DRAFT_SYSTEM.md` が指示する `{"target": "draft"}` を、スキーマが拒否していた。
4. 進捗の妨害に場所の制約がなく、遠隔地から妨害できた。
5. ドラフトの指名は公開なのに、取られた専属依頼が他パーティーの掲示板から消えていた。
6. `finalize_session.ts` にCLIの入口がなく、ワークフローどおりのコマンドが何もしていなかった。

## 設計上の課題（未対応・判断が必要）

1. **首位が飢える**: 中盤ドラフトでは評判の逆順により、首位の銀羽根団が最後に選んだ。その時点で専属依頼は残っておらず、共同依頼への誘いも、相手が2件ずつ依頼を抱えていたため受けられなかった。GMが追加の依頼を出すまで、銀羽根団には進める依頼がなかった。対策の候補は次のとおり。
   - 候補に専属依頼をパーティー数以上入れる規則にする。
   - 誘いを受けるときに限り、受注上限を超えてよいことにする。
   - 1回のドラフトで取れる専属依頼を1件までにする。
2. **衝突が膠着しやすい**: 進捗+2に対して妨害-2が釣り合い、衝突した依頼の組が両方とも期限切れになった。妨害の効果を進捗より小さくするか、必要進捗を下げる余地がある。
3. **共同依頼が成立しにくい**: 受注枠が埋まると、誰も共同依頼に参加できない。その結果、疫病のクロックは防ぎようがなかった。物語としては成立しているが、選択の余地がなかった点は問題である。
4. **士気に機械的な意味がない**: 灰灯団の士気は2まで下がったが、判定にも行動にも影響しない。修正値に結びつけるか、指標から外すか、どちらかにすべきである。
5. **ドラフトのエントリの actions は最後の応答だけ**: 各指名の内容は `draft.picks` に残っているので、記録として欠落はない。ただし形式が不揃いである。

## 検証方法の限界

- **情報の漏洩**: 1つのエージェントがGMと全パーティーを担当したため、隠された情報を知った状態でパーティーの判断をしていた。実際、ドラフトで灰灯団が「オラは台帳に倍額を払う」という、この世界には存在しない知識を根拠にした（直前の動作確認で作った世界の内容が混入した）。情報の非対称を本当に検証するには、パーティーごとに別のエージェント（サブエージェント）を立て、そのパーティーのリクエストファイルだけを渡す必要がある。
- **規模**: 3パーティー・6ターン・1シードの結果であり、傾向の確認にとどまる。
- **小説化は未実施**: 物語として面白いかどうかは、`narrative_replay.md` を生成して読まないと判断できない。
